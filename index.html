视频内容视觉化总结

把 ChatGPT 从“聊天工具”变成可交付成果的数字员工

核心不是学习编程，而是给足上下文、明确交付结果，并要求系统执行、验证和修正。

给足上下文 → 明确目标 → 执行任务 → 验证结果 → 持续迭代

这套方法适用于文档、数据、自动化、网页、知识库和销售项目。

先分清三种角色

Chat、Work、Codex不是强弱关系，而是任务类型不同。

01 · CHAT

讨论与判断

适合问答、推演、快速分析和思路碰撞。

快速对话优先
02 · WORK

多步骤交付

适合研究、报告、文件处理和完整成果交付。

项目化成果优先
03 · CODEX

技术执行

适合代码、GitHub、自动化、文件系统和工具搭建。

可执行可验证

7 个核心办法

每一项都对应一个常见失败点：目标模糊、上下文缺失、缺乏验证或项目规则失控。

方法 01

不要只提问，要下达任务

明确输入范围、处理动作、交付形式、权限边界和验收标准。

方法 02

先规划，再执行

先检查环境和风险，再开始修改。

方法 03

用项目保存长期上下文

把长期规则写入 README、AGENTS、TASKS 和 CONTEXT。

方法 04

直接操作文件

围绕文件夹完成扫描、整理、修改和输出。

方法 05

要求验证，不只生成

报告查数字，表格查公式，网页查交互，自动化实际跑一次。

方法 06

用截图和样例表达

给参考页面、旧报告、模板或成功案例。

方法 07

持续迭代

第一版用于暴露问题，明确反馈后逐步修正。

背景 + 目标 + 输入 + 执行步骤 + 输出格式 + 限制条件 + 验收标准

提示词不需要堆砌形容词。真正有效的是明确责任边界，以及什么才算完成。

推荐执行流程

1检查环境
2制定计划
3开始执行
4运行验证
5修正问题
6交付成果

必须控制的 3 个风险

权限过大

只开放具体项目目录；删除、覆盖、发送和上传必须确认。

生成不等于完成

所有任务都必须加入可执行的验收标准。

上下文污染

长期规则、当前任务和历史归档分层管理。

最终只需要记住这 7 句话

01 Chat 用于讨论，Work 用于交付，Codex 用于执行。
02 不要问它能做什么，直接说明要交付什么。
03 复杂任务先规划，再执行。
04 长期规则必须写进项目。
05 让系统直接处理文件。
06 任何结果都必须测试和验证。
07 从真实、重复、耗时的工作流开始。
